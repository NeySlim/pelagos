# Pelagos 0.4.0

Draft: each lot of the program adds its bullets under the right section; the release commit turns this into the final notes.

## Behaviour changed
- Applied plans can be rolled back for 24 hours (`plans.rollback_window_seconds`, 10 minutes to 7 days); `plans.ttl_seconds` now only bounds the preview, and a failed rollback is final.
- Rolling back an update plan only withdraws a rollout no node has started; once started, finished or replaced, the rollback is refused (409) and the Updates screen's actions take over.
- Sizes use binary units (KiB, MiB, GiB; Kio, Mio, Gio in French) with the separators of the language.
- Plan dialogs close with "Close" ("Fermer"), and the French rollback button reads "Revenir en arrière".
- A viewer with `read:audit` can open any plan, read only.
- Rollback guards hold for the whole window and refuse before writing anything (409, the plan stays applied): a DHCP rollback after any later change of the Kea configuration, or whose guard record is lost; a D2 configuration rollback after a restart of the process that applied it; a BIND configuration rollback whose backup is gone. Backups are now kept at least as long as the rollback window, whatever `retention.backups_days` says.
- On several nodes (an HA pair, a host plan), a rollback first asks every node's guards: if one node refuses (a hand edit on the partner only, a lost guard record), no node is rolled back (409, the plan stays applied); a node that does not answer also refuses it (409, retry once it is back). A node that still refuses during the rollback stops it before the others, and each part of the plan shows whether it was rolled back.
- DHCP forms (subnets, shared networks, classes, options, reservations): "Preview the plan" is disabled until a field differs from the edited object, and a submit without change builds no plan ("No difference").
- Restarting the web service or upgrading a node no longer signs anybody out: the session cookie is signed and every node of the cluster takes it over (`auth.session_resume_enabled`, on by default; off goes back to one login per node and per restart).
- Removing a node signs everyone out of the other nodes once: the session signing secret is replaced so the removed node cannot open sessions.
- `pelagos user reset-password` ends the user's open sessions on every node once replicated; `disable-totp` and `remove-keys` leave them.
- A Kea configuration plan whose target node is offline now answers `409 node_unreachable` (it was `409 preflight_failed`), naming the nodes and saying whether it may apply in part.
- While a node waits for the reconciliation of a partial apply, Kea configuration plans that target it answer `409 reconcile_required`.
- **Records**: a record value that does not parse as its type is refused at once with `400 validation_error` naming the value (`changes[i].after.rdata[j]`) and the expected form, instead of a failed plan (`422`); the desired state RRset verbs do the same.
- **Records**: the default `dns.update_types_admin` gains SSHFP, TLSA, HTTPS, SVCB, NAPTR, LOC, DNAME, DS and URI; a cluster still on the former default is upgraded, a list edited by hand is kept. Zones whose `update-policy` lists the former types explicitly get an `update_types_narrow` finding in the security audit, whose plan widens the grant.

- `ipv6.poll_seconds` is now `discovery.poll_seconds` (renamed on upgrade): it paces the DHCPv6 lease walk and the new IPv4 neighbor read. A node still on 0.3.x reads its default (300 s) once the cluster is upgraded.
- **Backups**: turning scheduled archives on needs a tested archive key: paste its private key under Administration > Backups, Test my key (`POST /admin/archives/keys/{recipient}/verify`, never stored); otherwise `409 archive_key_unverified`. A cluster already scheduled keeps archiving and gets the `archive_key_unverified` warning until a key is tested, and again every `archives.key_reminder_days` (90).

## New
- **Plans**: `GET /plans` lists the plans of the node, newest first, filtered by state, user and scope; `GET /audit?plan_id=` lists every audit entry of one plan; the WebSocket event `plans`/`expired` fires when a plan leaves the node. Finished plans survive a restart of the web process within their window.
- **Search**: `GET /search?q=` searches zones, records, leases, reservations, hosts, open alerts and nodes at once (names, address prefixes, MAC or DUID with or without separators), each group filtered by the caller's permissions.
- **Desired state verbs** for scripts, Ansible and Terraform: `PUT` and `DELETE` on RRsets, zone declarations, DHCP reservations, subnets, client classes and global options build and apply a plan only when the object differs (a repeated call answers `{"changed": false}`); `?dry_run=1` returns the plan; `If-Match` on the `ETag` gives optimistic concurrency (`412`). They need the object's read permission as well as the plan's write permission. New reads with an `ETag`: RRsets, reservations, client classes and options.
- **Replication**: a write lost to a concurrent write of another node is recorded (`replication.conflict` audit entry naming both authors, secrets and password hashes masked) and raised as a `replication_conflict` info alert that clears 24 hours after the last conflict. Each node keeps `cluster.bases.json` next to `cluster.toml`; it is not archived, and `pelagos restore` removes it when it puts back a restored `cluster.toml`.
- **Cluster**: generic replicated collections, the foundation for the coming IPAM, SSO, templates, delegation and approval records; a node on an older release ignores them and never deletes them.
- **Node site**: an optional `site` label per node (`pelagos init --site`, `pelagos enroll --site`, `PATCH /nodes/{id}` with `admin:nodes`, audited as `admin.node.replace`), replicated with the node; a node on an older release ignores it and never deletes it.
- **DHCP with a partner offline**: a Kea configuration plan (subnets, shared networks, reservations, classes, options) can apply on the reachable nodes only when an HA partner is powered off or its Kea is stopped (`POST /plans/{id}/apply` with `partial: true`, confirmation required). The skipped node is recorded in the replicated `kea_partials` collection, the `config_divergence` alert opens at once (critical once the node is back unreconciled), and `POST /dhcp/{family}/config/reconcile/plan` copies the shared configuration onto it, flagging changes made on both sides. A partner whose Kea still answers is never skipped. Needs 0.4.0 on every reachable node.
- **Record types**: SSHFP, TLSA, HTTPS, SVCB, NAPTR, LOC, DNAME, DS and URI can be added, replaced and deleted in dynamic and static zones, from the editor and the API. DS only at a delegation (never at the apex nor below another delegation), nothing below a DNAME, one target per DNAME, DNAME and NS together only at the apex; an SVCB for DNS (`_dns`) without `alpn` is refused before the plan, as named would.
- **Zones on a secondary node**: the records of a zone whose primary is another node of the cluster can be edited from the secondary; the plan is applied on the primary, and the screen says so. An external or unreachable primary keeps the zone read only, with the reason.
- **Lease history**: the collector records when each address was given, renewed, taken over by another client, released, expired or deleted (`lease_events` in the series cache, schema version 2, migrated in place); `GET /dhcp/{family}/leases/history` (filters `ip`, `mac`, `duid`, `hostname`, `since`, `until`) and `GET /hosts/{key}/timeline` read every node. Settings `collector.lease_history_enabled`, `collector.lease_history_renew_seconds`, `retention.lease_history_days` (90).

- **Sessions on every node**: a session opened on one node works on every node reached under the same name (a load balancer with TLS passthrough or a DNS round robin in front of the UI); signing out, changing a password, disabling a user or changing their roles ends their sessions on every node within seconds. New audit action `auth.resume`; `auth.logout` names the session by a one-way handle.
- **Prometheus metrics**: `GET /metrics` (text format, outside `/api/v1`) serves the node, pool, zone serial, DDNS, alert and HA readings of `pelagos-metrics.py` plus BIND query, response and transfer counters, Kea packet and lease counters per node, plan outcomes and the build version. A token with `read:series` (a `viewer` token) or a client of `metrics.allowed_networks` reads it; `metrics.endpoint_enabled` turns it off. It is never audited, so frequent scrapes no longer fill the audit log. `scripts/examples/grafana-pelagos.json` is a ready dashboard; `pelagos-metrics.py` is deprecated in favour of the endpoint and keeps working.

- **Discovery** (module `discovery`, off by default): each node reads its IPv4 neighbor table every `discovery.poll_seconds`; hosts gain `seen` (first and last sighting, node) and `vendor` (manufacturer from the IEEE MAC prefix registries shipped with the package); `GET /hosts/discovered` lists every device seen, `?filter=unknown` those no lease, reservation or record accounts for; `GET /hosts/vendor/{mac}`; new info alert `unknown_device` after `discovery.unknown_after_minutes` (60), silenced per MAC by an exception. Settings `discovery.ipv4_enabled`, `discovery.unknown_after_minutes`, `retention.neighbor_observation_days` (30).
- **Backups**: `pelagos restore --verify <archive>` proves an archive restorable without root and without touching the host (sums, decryption, `node.toml`, `cluster.toml`, `named-checkconf`, `named-checkzone`, `kea-dhcp4|6 -T`, `kea-dhcp-ddns -t` on copies), with a report and exit status 0 or 1; the scheduled test restore now also checks `cluster.toml` and uses `kea-dhcp4|6 -T` when the daemon does not answer.

## Interface
- **DHCP subnets**: the subnet detail opens in a floating window and the table uses the full width; the subnet form edits the minimum, default and maximum valid lifetime, pools as editable rows with validation and options as name and data rows; a pool with declined leases links to the leases of the subnet in the `declined` state; the greyed subnet ID and reservation identifier fields say how to change them (delete, then recreate).
- The reasons, confirmation and Close, Roll back and Apply buttons of a plan form an action bar that stays on screen, in dialogs and on phones; a diff over 10 lines starts folded with its line count; validations name the node they ran on and the nodes the plan applies to.
- Error notices show a translated title per error class (load failed, forbidden, not found, unavailable, network); the technical text is folded under Details.
- Tables can show as cards on phones; clickable rows and cards are focusable and open with Enter or Space; header tabs keep their label on phones and scroll sideways; detail windows can open wide.
- **DNS zone page**: a note says why each action is missing (zone changes, rndc operations, records) for roles that lack the permission; the primary node of a copy is a link to that node, "Notify" is listed but disabled on a copy with "on <node>, primary", and the secondaries note points to the primary.
- **RPZ**: the category cards no longer have a button each; changed cards are marked "modified" and one "Save the categories" button in the footer builds a single plan; the log times follow the language, sizes use binary units, and the node RAM line is explained.
- **Zones list**: the banner for zones declared in your own named.conf files reads "N zone(s) are declared ...: Pelagos reads them without changing them. Hand them over to edit them here."
- The plan preview offers "Apply only on the reachable nodes" after a `node_unreachable` answer, adds the confirmation it needs, and lists the skipped nodes with the reason.
- The record editor offers assisted fields for the new types (SSHFP algorithm and fingerprint type lists, TLSA usage, selector and matching type, HTTPS and SVCB priority, target and parameters, NAPTR, LOC from decimal degrees, DS, URI) and checks each value as typed.
- Higher contrast for tertiary text in the Gray, Purple and Sunset themes; accessible names for the search box and the live-updates indicator.
- **Account**: the page is split in Profile, Security, API tokens and Preferences tabs (the `#securite` anchor still opens Security); the profile lists the other nodes of the cluster with links to their web UI.
- **API tokens**: a user with no second factor sees why, with a link to the Security tab, before any creation form; the administration token list falls back to cards on phones.
- **Reasons on greyed controls**: certificate buttons of an unreachable node, the per-node Kea DHCPv6 switch of Modules and the Backups node card say why they are unavailable; the Kea editor explains that the root cannot be edited in bulk.
- Pages of Account, Administration and the Kea editor show the translated error notice instead of a raw message; Backups sizes follow the shared size format.
- **Plans page** (Admin group of the menu, right after Audit log): the plans of the node you are connected to, with state, author, summary, nodes and a countdown to the end of the rollback window; filters by state and author; the detail opens read only and offers Roll back only to the plan's creator or an admin while the window is open. The audit links `*.apply` and `*.rollback` entries to their plan, and `/audit?plan_id=` filters one plan. The "Plan applied" toast adds "View in Plans".
- **Hosts, alerts, nodes, dashboard**: a one-line note says which permission a missing action needs (new host, alert acknowledgement, node enrollment); the hosts, alerts and nodes tables show as cards on phones; the "Found in" column lists the parts a host has and strikes a DNS record its alerts say is missing; alert buttons name where they lead ("Open subnet 3", "Open DHCPv4 HA", "Open the nodes"); "Ignore (exception)" asks for its reason inside the alert detail; dashboard tiles show short HA states with the full one as a tooltip and alert titles on two lines.
- **Node sites**: nodes group by site in the Nodes table and carry a site badge on the dashboard cluster trace once at least two sites exist.
- **Global search**: `Ctrl+K` (`Cmd+K` on a Mac) or `/` opens a search over hosts, zones, records, leases, reservations, alerts and nodes (a partial MAC, an address or a name); results are grouped, keyboard driven and open the page or the host sheet.
- **Sidebar and phone menu**: the sidebar folds to icons and remembers it; the phone menu folds its sections, marks DHCPv6 entries with "v6" and has a search button.
- **Languages**: the language list follows the folders of the frontend `locales/` (a new language needs no code), a test lists the keys a new folder lacks, notification catalogs are generated for every folder; see `docs/dev/i18n.md`. English "Read at" reads "Collected at".
- **Zones list**: zones show as cards on phones.
- **Backups**: each recipient shows when its private key was last tested, with a Test my key button; the schedule switch says why it stays off.

## Fixes
- **Hosts**: the hosts view and the consistency pass no longer read every lease and transfer every zone on each request: a zone is transferred again only when its serial moves, and sources refresh on lease, zone and plan events, at the latest after `collector.hosts_cache_max_age_seconds` (60 s).
- **Security**: a node's `web_url` must be an http(s) URL with a host; enrollment refuses anything else with `400 validation_error` before using the token, stored or replicated values that are not http(s) are ignored, and node links are made only for http(s) URLs.
- **Zones**: a zone name may contain "/" only in the first label of an RFC 2317 classless name (`0/25.2.0.192.in-addr.arpa`); `example.lan/records` no longer creates a zone.
- **Zones**: a zone target without a view whose first label is RFC 2317 (`0/25.2.0.192.in-addr.arpa`) lands in the default view instead of being read as view `0`; the same for the zones named in the dynamic DNS failover requests.
- **Tables**: a failed read in a table shows the translated error notice (details folded, Retry) and never the empty state beside it.
- **Zone page**: the help of "Edit the local copy" is a visible note, linked to the button for screen readers, no longer a tooltip.
- **Plans**: a D2 configuration plan can be rolled back for the whole window, no longer only `plans.ttl_seconds` after its apply; Kea keeps its rollback guards 7 days instead of the last 256 plans.
- **Static zones**: a zone file with an SVCB or HTTPS record written `alpn="h2,h3"` (no space around the quotes) is read again; it failed with "whitespace after =".
- **Backups**: two writes in the same clock tick no longer fail with "File exists"; the backup directory gets a numeric suffix.
- **Replication**: a failure writing `cluster.bases.json` no longer fails the config write or `PUT /repl/v1/config` after `cluster.toml` was written; it is logged as a warning and conflict detection skips that entry.
- **Web service**: reading a large zone (records page, record and host plans) no longer stalls the other requests of the web process, `/health` included, for up to two seconds: the transfer now lets them in every 20 ms.
- **Web service**: gunicorn's control socket is no longer opened in the service account's home; nothing used it, and it could add workers to the single-worker web process.

## Upgrade
- Behind a load balancer without session affinity, every switch between a 0.3.x and a 0.4.0 node asks to sign in again during the rolling upgrade: use affinity for the upgrade window, or upgrade the nodes one right after the other. A load balancer that terminates TLS in front of the UI is not supported.
