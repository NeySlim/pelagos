# Releasing Pelagos

1. Write `docs/releases/X.Y.Z.md` (starts with `# Pelagos X.Y.Z`) and a `## X.Y.Z` section in `CHANGELOG.md`, then `make release VERSION=X.Y.Z`: it runs `scripts/release-check.sh`, commits `chore(release): X.Y.Z` with the notes, tags `vX.Y.Z` and opens the next `.dev0`.
2. `git push origin main vX.Y.Z`: the `release` workflow runs the full CI, builds and tests the debs (amd64, arm64 on native runners) and the rpms (el9, el10) of the tag, pushes the tested images to ghcr.io as candidates only (`X.Y.Z-amd64`, `X.Y.Z-arm64`, their digests kept as the run's `image-digests-X.Y.Z` artifact), runs the blocking checks and drafts the GitHub release (tested packages, `release.json`, `NOTES.md`, `SHA256SUMS`). `X.Y.Z` and `latest` do not move yet.
3. Review the draft on GitHub, then click **Publish**: nothing publishes it by itself. A failed or repeated run (Actions, `release`, Run workflow with the tag) replaces the draft's files and the candidates.
4. Publishing starts `release-published`: it takes the digests of the newest successful `release` run of the tag, checks that each candidate tag still holds them, and points `X.Y.Z` (both arches) and `latest` at them with `docker buildx imagetools create`, without rebuilding (`scripts/release-images.sh`). `latest` only moves for the newest published release. The draft is created with `GITHUB_TOKEN`, whose events start no workflow, but the person who publishes it does start `release-published`. If it fails (digests expired after 90 days, candidate replaced), run `release` again with the tag.
5. A manual run on a release that is already published leaves the release as it is, rebuilds and tests the images and promotes them itself (`X.Y.Z`, and `latest` if it is the newest release).
6. Production takes those same files: `scripts/deploy-prod.sh --tag vX.Y.Z --dry-run ns2 ns1`, then without `--dry-run` (it downloads the draft or release with `gh`, checks `SHA256SUMS` and `release.json`, standby first).
7. Final versions only (`vX.Y.Z`: GitHub renames asset names with `~`); `make release NO_TAG=1 VERSION=X.Y.Zrc1` builds local debs of `HEAD` for lab tests, never for production. Optional signing: repository secret `PELAGOS_RELEASE_KEY` (Ed25519 private key PEM, `PELAGOS_RELEASE_KEY_PASSWORD` if any).
